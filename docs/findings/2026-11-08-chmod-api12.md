## Uniform registration — Researched, implemented/compiled

Primary implementation: `tools/native_assets/uniform_contracts.h`,
`tools/chmod.ps1`; existing native codec/import/augment functions in
`tools/asset_codec.cpp` and `tools/native_assets/`; Studio Xbox uniform cloning
and native roster routing were used as source leads, not PS3 behavior.
The existing augment path registers name-hash banks and rebuilds the runtime map.
New code admits only matching standard uniform templates and unchanged record,
component and nontexture layout. Sanitized metadata binds new name/hash identities;
new recognized pixel payload identities must be private. World/selection pairing
and native roster owner/team linkage are checked together. Team uniform-owner
field is +0x190 in the Xbox team row, matching Studio's parser.

Limitations: source-compatible texture artwork, no topology import. Known catalog
texture identity checks do not add renderer bind-time owner tracking or prove all
opaque resources are understood. No authored retail uniform package or gameplay
observation was produced. Offline source agreement is not gameplay verification.

## Player weight hook — Researched, implemented/compiled

Studio `choops_recomp/data/xbox_player_fields.json` records Xbox getter 84752968,
setter 848425d8, raw row byte156 with anchor bias16, shift5/9bits, menu100..400.
Generated `port/generated/default/ch2k8_recomp.12.cpp` getter loads BE32 at
r3+140, rotates by27 and masks 0x1ff into r3. The identity and original body are
therefore supported independently by generated guest code.

Generated `ch2k8_pch.h` DEFINE_REX_FUNC supplies weak `sub_` aliases and retains
`__imp__sub_` bodies. The strong `REX_HOOK_RAW(sub_84752968)` in
`port/src/mod_extensions.cpp` calls the original and replaces only the result.
The registry uses `sub_84752968`; direct symbolic references resolve the same
strong wrapper. No guest PPC address is treated as a native patch address.
The final linker map shows original at 0x14047f190 and wrapper at 0x142b8f840
for this build, in generated and mod_extensions object files respectively.
These host addresses are build evidence, not a mod API or future stable addresses.

SDK rex_app.cpp initializes OnPostSetup before guest Resume. `main.cpp` loads
approved extensions during that phase. Atomic callback publication, process-long
module lifetime, preserved host FP state and bounded return values are implemented.
The versioned C ABI exposes no PPCContext pointer. The sample DLL was compiled
and packaged, never loaded. Indirect registry dispatch and symbolic direct calls
are covered by linking; raw field readers and unrelated getters are not intercepted.
No physics, gameplay, Legacy or scorebug change is proven.

## Native saves and mixed activation — Researched

See previous [backend findings](2026-11-08-chmod-backend.md) for actual Roster.ROS,
0x148 SDK aggregate header, XUID/title paths and native relationships. API 1.2
includes registered banks and extension digests in profile identity. Code-only
profiles seed a validated baseline roster pair if present, or use built-in data;
partial pairs reject. User/Settings may be seeded, existing Legacy saves are not.
This protects normal profile switching, not against malicious unsandboxed DLLs.

## Automatic alternate activation follow-up

User requested that added alternate folder pairs enable native roster links across
available Dummy HDD rosters. Implemented in `activate_roster_uniforms` in
`tools/native_assets/mod_contracts.h`, `Sync-ChmodRosterActivation` and
`Restore-ChmodRosterActivation` in `tools/chmod.ps1`, and launch preparation.

Evidence: Studio `uniforms.py` `owner`, `rows`, `append`, `create`, and `name`:
owner=word0 bits22..31, artwork=12..21, variant=8..10, unlock=0..6; word1
shape/unknown bits copied from Home. Uniform table count at body0x70, relative
pointer at0x74 uses bias1. Studio append aligns a new table and changes only that
descriptor; native save outer BE32 length must change with the appended body.
The source convention maps h/a/x/y/z to Home/Away/Alternate1/2/3. Native
activation independently validates the same Xbox tables and relationships before
and after staging. Header remains byte-identical.

SDK `src/system/xam/content_manager.cpp` ResolvePackagePath/ResolvePackageHeaderPath
uses actual content filename under XUID/title/type and a parallel .header, rather
than restricting the SDK to Roster.ROS. Discovery therefore accepts structurally
validated named .ROS pairs, requires header filename agreement and neutral/matching
storage XUID. This is structural source evidence; no additional real named save
or gameplay observation was obtained. Conservative ASCII filenames only.

Automatic matching uses existing roster Home/Away artwork identity, never numeric
team-index assumptions. Existing explicit same-art alternate links also work.
Conflicting routes and ambiguous/no owner stop activation. Editor XRUFv001 dormant
metadata is not native game data and rejects for manual restoration in Studio.
All available supported rosters in the current HDD root and selected mod profile
are staged together; inactive profile roots wait until selected. Explicit manifests
still bind every discovered bank's source and integrity. No arbitrary folder name
is accepted as sufficient evidence of loadable Xbox artwork.

Backups/journal support crash interruption and unchanged-file rollback. If the
player/game edits a managed save, switching rejects rather than reverting those
edits. No Legacy files are processed. This conservative behavior is a limitation,
not a save-merging claim. Test source `tests/test_chmod_uniform_activation.py`
covers named/default save staging, append preservation/idempotence and unsafe
mapping rejection; it was authored but NOT RUN. No live save was modified and no
game or popup was opened/closed by this work. Status remains Researched, compiled
only; functional/user acceptance pending.

Vanilla follow-up: normal launcher starts also clear the known unlock field on
all existing native uniform rows (Home/Away/Alternate), independent of mod folder
presence. Native `vanilla-uniforms` enumerates canonical Xbox X/Y/Z names, matches
both name CRC identities against the original catalog with fixed XEX gate, and
supplies optional routes. Unused base artwork skips; conflicting existing art is
preserved/unlocked. Required mod-added art remains strict. The existing prepared
cache copies original resources before replacements, providing original-artwork
fallback when no mod payload exists. Recovery launch bypasses these changes.
This is source-derived functionality only; actual menu unlock gating and rendering
remain for user acceptance and may have additional executable constraints.

The final helper includes automatic activation and vanilla discovery and was
compiled/deployed without execution. Optional vanilla candidate owner ambiguity
skips creating a guessed route while still unlocking existing rows. Required mod
folder mappings reject ambiguity. Actual saves remain unchanged until the user
launches normally; this continuation performed no tests or game/popup interaction.

## Researched, not enabled in package API

**SCNE/components and added banks.** Read `tools/native_assets/folder.h`,
`import_layout.h`, `prepare.h`, `tests/test_native_asset_tools.py`, and Studio
`docs/XBOX_FORMATS.md`, `UNIFORMS.md`, `ROSTER_RELATIONSHIPS.md`. The native tool
already has checked bank registration/paired components and structural size
rules. Studio resolves Xbox roster uniform routing and reports offline
preservation checks. Its `XRUFv001` is editor metadata, explicitly not a console
save wrapper. Source-compatible geometry editing and new uniform activation need
package-level component ownership/topology contracts and in-game acceptance.
Neither an editor preview nor fixed byte count establishes source compatibility.

**Dummy HDD.** The pinned SDK's
`work/third_party/rexglue-vulkan/src/system/kernel_state.cpp` constructs
`ContentManager` with the supplied user-data root. In
`src/system/xam/content_manager.cpp`, `ResolvePackageRoot` formats uppercase
16-hex XUID, 8-hex title ID and 8-hex content type; `ResolvePackagePath` appends
the game's content filename and honors aggregate-data XUID selection.
`ResolvePackageHeaderPath` uses a parallel `Headers/<type>/<filename>.header`.
`ContentPackage` mounts the package directory via writable HostPathDevice.
`InstallContent` has an STFS marketplace installation path; that is not evidence
of CH2K8 roster-save wrapping. Reviewed `tools/prepare_content_sdk.py`,
`port/src/content_roots.h` and the existing codegen/save-review finding: their
enumeration deduplication does not validate a save writer. Actual game roster
filenames, inner payload, header/wrapper requirements and profile transitions
remain unresolved. No save install, rename, overwrite or migration is exposed.

**Hooks/scorebug.** Reviewed `port/ch2k8_manifest.toml`, all config includes,
`docs/symbols/symbols.csv`, hot-function records, Ghidra export scripts and
the codegen/save findings. ReXGlue compile-time `midasm_hook` probes at guest
`84DCB314` / `84DCB318` bracket VdSwap with `registers=[]`; they are frame timing
probes, not verified scorebug/menu/gameplay/Legacy semantics. Existing generated
function overrides use the project's PPC ABI and are compiled into the binary.
No dynamic package hook dispatcher with a verified gameplay contract was found.
No guessed function hints, native address patcher, arbitrary guest dispatch, DLL
loader or speculative extension ABI is introduced. A new hook point needs
research/codegen integration and documented arguments/lifecycle first.

## Remaining acceptance and work

No game launched or gameplay success claimed. Required manual acceptance: boot
the pristine supported installation, activate visible user-authored DDS artwork,
observe `Native DDS upload` and the correct owner in menus/gameplay/replay,
disable and compare baseline; exercise Mods controls, shared-identity conflict,
bad update and mods-disabled recovery. Existing renderer/audio support is
unchanged. Native PCM and Studio's offline model/roster work are research inputs,
not new package capabilities. The complete seven-step request is intentionally
not marked complete: the first two steps and isolated texture proof are the
supported slice; subsequent game/save/hook research and in-game proof remain.

Current tradeoffs: full-copy caches per launch, no automatic cache collection,
manual update download, no parallel launcher transaction coordination. Atomic
install/settings/cache publication preserves the prior data on ordinary failure;
a killed process may leave its hidden stage for manual cleanup. No user save
backups are needed by this slice because it never writes saves. Junction test
may skip where the sandbox forbids creating a junction; ZIP symlink rejection
remains covered without creating a filesystem link.
